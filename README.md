**Передавайте задачи от Codex к OpenCode и держите выполнение под контролем.**

Local Agent Bridge связывает локальных ИИ-помощников через файлы и общую доску.
Помощник передаёт задание, OpenCode запускает его на вашем компьютере, а мост
фиксирует начало работы и код завершения под одной меткой задачи.

**Бесплатная локальная альтернатива Desktop Commander Remote для передачи задач.
Количество вызовов и запусков моста не ограничено.** Исходники открыты по MIT.
Нужен помощник с уже доступным локальным терминалом; тарифы и квоты выбранных
моделей и ИИ-клиентов сохраняются.

Демо использует настоящий CLI моста и локальный тестовый исполнитель вместо

## Что вы получаете

| Задача | Как помогает мост |
|---|---|
| Передать работу другому помощнику | Отправляет UTF-8 задание в отдельный запуск OpenCode |
| Понять, завершился ли запуск | Связывает начало, код завершения и ошибки меткой задачи |
| Согласовать работу нескольких агентов | Хранит статусы, результаты и передачи работы в общей доске |
| Продолжать работу в своём темпе | Число запусков не ограничено; тайм-аут задаётся по желанию |
| Развернуть мост на другом ПК | Достаточно папки проекта, Python и установленного OpenCode |

Мост использует стандартную библиотеку Python. Весь его код находится в
репозитории. Доска хранится на вашем диске; сервер моста в облаке не требуется.
Запуск модели использует выбранного вами провайдера OpenCode.

## Быстрый старт

Установите Python 3.10+ и OpenCode, выполните вход к своему провайдеру, затем:

```powershell
git clone https://github.com/pulvasnecov-hash/local-agent-bridge.git
cd local-agent-bridge
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
.\bridge.cmd send .\examples\task.txt --dry-run
```

Последняя команда покажет, как будет запущена задача. Для реального выполнения
уберите `--dry-run`. Оно использует ваш доступ и тариф OpenCode.
Если Git не установлен, воспользуйтесь кнопкой **Code → Download ZIP** или
[скачайте архив](https://github.com/pulvasnecov-hash/local-agent-bridge/archive/refs/heads/main.zip).

## Как проходит задача

```text
Локальный помощник → UTF-8 task-файл → bridge send → OpenCode
                                           ↓          ↓
                                     handoff      результат процесса
                                           ↘      ↙
                                        bus.jsonl
```

OpenCode получает отдельное задание с закрытым stdin и `--standalone`.
Аргументы передаются без shell; поддерживаются пробелы и кириллица в путях.
Мост записывает `handoff`, затем `result` или `blocker`. Вывод OpenCode виден
в терминале. Код 0 подтверждает завершение процесса; результат работы проверяется
по изменённым файлам, тестам или другому подходящему свидетельству.

## Установка на Windows

Нужны Python 3.10+ и установленный OpenCode с настроенным входом к выбранному
провайдеру. Мост не устанавливает их и не меняет их конфигурацию.

Скачайте или клонируйте репозиторий. В PowerShell из его папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
.\bridge.cmd doctor
```

Установщик создаёт только `bridge.local.json` рядом с собой. Повторный запуск
сохраняет существующий конфиг. Он не добавляет автозапуск, PATH или службу.
`doctor` проверяет поиск Python, настроек и исполняемого файла OpenCode.
Он не вызывает модель и не подтверждает доступ к провайдеру или запись в папки.

Если автоматический поиск не нашёл OpenCode, задайте путь к нативному `.exe`:

```powershell
.\install.ps1 -OpenCodeExecutable 'C:\Tools\OpenCode\opencode.exe'
```

Для уже созданного конфига измените `opencode_command` вручную. Windows-обёртки
`.cmd`/`.bat` вместо исполняемого файла не принимаются.

## Первая задача

```powershell
# Предпросмотр команды: без запуска, записи журнала и расхода модели
.\bridge.cmd send .\examples\task.txt --dry-run

# Реальное выполнение: использует существующий вход и тариф OpenCode
.\bridge.cmd send .\examples\task.txt --cwd 'C:\Work\MyProject' --task first-check

# Прочитать результат процесса
.\bus.cmd read --task first-check
```

Для выполнения с конкретной моделью добавьте `--model provider/model`.
Без модели в конфиге и командной строке выбор остаётся за OpenCode.
`--timeout 300` ограничивает запуск пятью минутами; по умолчанию лимита нет.
`--auto` явно передаёт флаг автоматического разрешения действий OpenCode;
по умолчанию мост этот флаг не добавляет. Действующие политики OpenCode остаются
применимыми. Плата за модель определяется выбранным провайдером и тарифом.

Коды выхода: код OpenCode; `2` — ошибка ввода/настроек; `124` — тайм-аут;
`130` — прерывание пользователем. Вывод OpenCode передаётся в текущий терминал.

## Общая доска

```powershell
.\bus.cmd post --from codex --kind handoff --task demo --to opencode --file .\examples\message.txt
.\bus.cmd read -n 20
.\bus.cmd read --kind result --task demo --json
```

Журнал только дополняется. Это соглашение для совместной работы; записи
`handoff` не блокируют редактируемые файлы. Перед правкой общего ресурса
помощники должны прочитать доску и согласовать пересечение работ.
Перед записью короткого сообщения эвристика отклоняет некоторые явные секреты.
Она не гарантирует отсутствие конфиденциальных данных.

## Настройки и переносимость

Все файлы реализации находятся в репозитории. `bridge.local.json` содержит
локальные настройки и исключён из Git; образец — `bridge.example.json`.

| Ключ | Значение по умолчанию |
|---|---|
| `opencode_command` | `[]` — поиск OpenCode; иначе массив: исполняемый файл и его аргументы |
| `model` | `""` — выбор OpenCode |
| `data_dir` | `.local` относительно файла настроек |
| `timeout_seconds` | `0` — без лимита |

Используйте `--config path.json` **перед подкомандой** либо переменную
`LAB_CONFIG`. Один конфиг означает одну общую доску. `send` передаёт его путь
дочернему процессу. Рабочая папка задания определяется `--cwd`, иначе используется
текущая папка вызывающего процесса. Не храните рабочие задания в отслеживаемых
файлах: используйте исключённый каталог `private/`.

На POSIX вместо `.cmd` запускайте `python3 bridge.py` и `python3 bus.py`.
Для конфигурации скопируйте образец в `bridge.local.json`; `install.ps1` нужен
только Windows. Блокировки рассчитаны на локальный диск, не на сетевой ресурс.

## Сравнение с Desktop Commander

Local Agent Bridge подходит для локального помощника, который уже читает файлы
и выполняет команды. Задачи передаются в OpenCode напрямую; квота Desktop
Commander Remote в этом маршруте не участвует.

Desktop Commander предоставляет Local MCP и Remote MCP. Его Local MCP тоже
бесплатен и не имеет месячной квоты. Тарифы Remote описаны на
[официальной странице](https://desktopcommander.app/pricing/);
[варианты подключения](https://desktopcommander.app/mcp/) проверены 27.10.2026.

Для удалённого доступа из облачного чата нужен соответствующий канал или
MCP-сервер. Local Agent Bridge предоставляет локальную передачу задач и доску
координации. История GUI-чатов и подключения между приложениями автоматически
не переносятся. Сравнение относится к этому сценарию работы.

Подробнее: [бесплатность и границы «без лимитов»](docs/LIMITS.md),
[доступ и конфиденциальность](SECURITY.md).

## Проверка и разработка

```powershell
python -m unittest discover -s tests -v
```

Тесты запускают локальный тестовый исполнитель и не вызывают модель.
GitHub Actions настроен для Windows/Linux и Python 3.10/3.13.
Фактический статус CI смотрите во вкладке Actions.

Проект вырос из рабочего локального моста Codex → OpenCode с обратной записью
результата в общую доску. Публичная версия убирает привязки к конкретному ПК
и включает все необходимые исходники. Это пользовательская интеграция.
Подробности стандартного запуска: [документация OpenCode CLI](https://opencode.ai/v2/docs/cli).
